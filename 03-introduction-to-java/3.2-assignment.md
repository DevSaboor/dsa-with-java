### Exercise 1 — Java Execution Pipeline

**Goal**
Make sure you understand what happens to a Java program between writing the source code and executing it.

**Task**

Explain the following pipeline in your own words:

```text
.java
  ↓
javac
  ↓
.class
  ↓
JVM
  ↓
Execution
```

For each stage, explain what happens and what the purpose of that stage is.

<details>
<summary><b>Click to reveal the Answer</b></summary>

```text
.java
  ↓
javac
  ↓
.class
  ↓
JVM
  ↓
Execution
```

* **`.java`** — Contains the human-readable Java source code.
* **`javac`** — Compiles the source code and produces Java bytecode.
* **`.class`** — Contains the generated bytecode.
* **JVM** — Loads and executes the bytecode on the host system.
* **Execution** — The program ultimately runs using the host system's native resources.

</details>

**What this teaches**
The basic Java compilation and execution pipeline.

### Exercise 2 — JDK vs. JRE vs. JVM vs. JIT

**Goal**
Understand the difference between the four commonly confused Java components.

**Task**

Explain the purpose of:

* **JDK**
* **JRE**
* **JVM**
* **JIT**

Then complete:

```text
JDK → ______ → ______ → ______
```

<details>
<summary><b>Click to reveal the Answer</b></summary>

* **JDK:** Provides tools and components needed to develop Java applications.
* **JRE:** Provides the environment required to run Java applications.
* **JVM:** Executes Java bytecode on the host system.
* **JIT:** Improves JVM performance by compiling frequently executed bytecode into native machine code.

The simplified relationship is:

```text
JDK
└── JRE
    └── JVM
        └── JIT
```

</details>

**What this teaches**
The roles and relationship between JDK, JRE, JVM, and JIT.

### Exercise 3 — Platform Independence

**Goal**
Understand why Java is considered platform-independent.

**Task**

Answer:

> Why can the same Java `.class` bytecode run on Windows, Linux, and macOS while a compiled C/C++ executable generally cannot be used directly across different operating systems?

<details>
<summary><b>Click to reveal the Answer</b></summary>

Java source code is compiled into **platform-independent bytecode**.

```text
              Java Source
                   │
                 javac
                   │
                   ▼
              Bytecode
              (.class)
             /    |    \
            ▼     ▼     ▼
          JVM    JVM    JVM
         Windows Linux  macOS
```

Each operating system has a JVM implementation capable of executing the bytecode on that platform.

C/C++, on the other hand, generally produces a **platform-specific native executable**, so the resulting binary is tied to its target OS and architecture.

</details>

**What this teaches**
Java's platform independence and the role of the JVM in **Write Once, Run Anywhere (WORA)**.

### Exercise 4 — Short Architecture Recall

**Goal**
Test whether you can recall the JVM's major responsibilities without looking at the notes.

**Task**

Without referring to the notes, briefly explain:

1. What does the **Class Loader** do?
2. What does the **Interpreter** do?
3. What does the **JIT Compiler** do?
4. What does the **Garbage Collector** do?
5. What is primarily stored in **Stack Memory**?
6. What is primarily stored in **Heap Memory**?

<details>
<summary><b>Click to reveal the Answer</b></summary>

1. **Class Loader** — Loads Java classes into the JVM.
2. **Interpreter** — Executes bytecode through interpretation.
3. **JIT Compiler** — Compiles frequently executed code into native machine code to improve performance.
4. **Garbage Collector** — Reclaims heap memory from objects that are no longer reachable.
5. **Stack Memory** — Primarily handles method call frames and local runtime data.
6. **Heap Memory** — Primarily stores objects and dynamically allocated data.

</details>

**What this teaches**
The main components involved in JVM execution and memory management.

<details><summary><b>Click to reveal the Answer</b></summary>
  
1. `Program.java` is the **human-readable Java source code** written by the programmer.
2. The `javac` compiler takes this source code and **compiles it into `Program.class`**, which contains **bytecode**.
3. This bytecode is not specific to one operating system or CPU, which is a major reason Java is considered **platform-independent**.
4. When the program runs, the **JVM (Java Virtual Machine)** loads the `.class` file and prepares its bytecode for execution.
5. The **Class Loader** brings the required classes into memory, while the JVM can initially use the **Interpreter** to execute bytecode.
6. The **JIT (Just-In-Time) compiler** can identify frequently executed code and compile it into **native machine code** for faster execution.
7. Finally, the JVM executes the resulting instructions, allowing the Java program to actually **run on the underlying machine**.

</details>
