# 💻 Chapter 01 — Introduction to Programming: Types of Languages & Memory Management

---

## 💻 What is a Programming Language?

At the hardware level, computers only process binary numbers—zeros and ones (`0`s and `1`s).

Writing instructions directly in binary is unpractical for humans.

A **programming language** allows developers to write instructions in a human-readable format.

The computer then converts these human-readable instructions into binary machine code (`0`s and `1`s) that the CPU can execute.

---

# 🧩 Types of Programming Languages (Paradigms)

Languages structure and process logic differently based on their paradigm.

Many modern languages are hybrid/multi-paradigm and implement features from more than one style.

```text
                Types of Languages
       _________________|_________________
      |                 |                 |
 Procedural        Functional      Object-Oriented
```

---

## 1. 🔄 Procedural Programming

* **Definition:** Specifies a series of well-structured, step-by-step procedures to complete a task.

* **Execution:** Follows a strict order of statements, functions, and commands.

* **Example Flow:**

```text
Input number 1
      ↓
Input number 2
      ↓
Calculate sum
      ↓
Display output
```

* **Languages:** Java, Python, C, C++ all support procedural concepts.

---

## 2. 🧠 Functional Programming

* **Definition:** Programs are constructed using pure functions.

* **Pure Functions:** Functions do not modify existing variables or global state; instead, they generate new data/objects as output.

* **First-Class Functions:** Functions can be treated like regular values—assigned to variables, passed into other functions, or returned.

* **Use Case:** Commonly used when performing many operations on an unaltered dataset, such as in Machine Learning.

* **Languages:** Python supports functional programming constructs.

---

## 3. 🏗️ Object-Oriented Programming (OOP)

* **Definition:** Programming paradigm centered around **Objects** and **Classes**.

* **Formula:**

```text
Object = Code + Data
```

* **Class:** A template or blueprint containing a named group of properties and functions.

* **Object:** A concrete instance of a class that resides in memory.

```text
Class: Human
(Template with properties: eyes, hands, name, roll_number)
         ↓
Object: Saboor
(Real instance occupying memory)
```

### Why OOP Matters

* Allows creation of complex custom data types (e.g., a `Student` entity holding `name`, `rollNumber`, and `marks`).

* Modularizes code into manageable parts, making programs easier to develop, debug, maintain, and reuse.

* **Languages:** Java, C++, Python support OOP.

# ⚡ Static vs. Dynamic Languages

Languages handle variable data types in two ways depending on when type checking occurs.

```text
Source Code ──(Compile Time)──> Machine Code ──(Runtime)──> Execution
```

---

## 🧱 Static Languages

* **Type Checking:** Performed at **compile time**.

* **Declaration:** You must explicitly declare the data type before using a variable.

* **Type Constraints:** Assigning an incompatible value or reassigning a different type to the variable results in a compilation error.

* **Trade-off:** Requires writing more explicit code, but provides greater type safety, performance, and catches errors early at compile time.

* **Examples:** Java, C++.

### ☕ Java

```java
// Static Language (Java)
int a = 10;     // Valid
a = "Saboor";   // Compile-time ERROR: type mismatch
```

---

## 🐍 Dynamic Languages

* **Type Checking:** Performed at **runtime**.

* **Declaration:** No need to declare data types; the language determines the variable's type automatically during execution.

* **Type Constraints:** A variable can point to an integer at one moment and be reassigned to a string later without error.

* **Trade-off:** Faster to write code, but type-related errors may remain undetected until the program is executed.

* **Examples:** Python, JavaScript.

### 🐍 Python

```python
# Dynamic Language (Python)
a = 10         # Valid (Integer)
a = "Saboor"   # Valid (Reassigned to String)
```

# 🧠 Memory Management: Stack vs. Heap Memory

In memory management, storage is divided into two primary regions: **Stack Memory** and **Heap Memory**.

```java
int a = 10;
```

* **Reference Variable (`a`):** Stored in **Stack Memory**.

* **Object / Value (`10`):** Stored in **Heap Memory**.

* The reference variable in Stack holds the memory address pointing to the actual object located in Heap.

```text
   STACK MEMORY                    HEAP MEMORY
┌──────────────────┐            ┌──────────────────┐
│   a (Reference)  ├───────────>│    10 (Object)   │
└──────────────────┘            └──────────────────┘
```

---

# 🔗 Key Principles of Reference Memory

## 1. 🔀 Multiple Reference Variables Pointing to One Object

More than one reference variable can point to the exact same object in Heap memory.

```text
a = [1, 3, 5, 9]
b = a
```

```text
   STACK MEMORY                    HEAP MEMORY
┌──────────────────┐            ┌──────────────────┐
│        a         ├───────────>│   [1, 3, 5, 9]   │
│                  │            │     (Object)     │
│        b         ├───────────>│                  │
└──────────────────┘            └──────────────────┘
```

---

## 2. ✏️ Object Mutation

If an underlying object is modified via one reference variable, the change is reflected across all reference variables pointing to that same object.

```text
a[0] = 99;
```

Accessing `b[0]` now yields `99` because `b` points to the same mutated Heap object.

---

## 3. ♻️ Unreferenced Objects & Garbage Collection

When a reference variable is reassigned to point to a new object, the previous object may no longer have any variable pointing to it.

```text
a = 10;
a = 50;  // 'a' now points to 50. Object '10' has 0 reference variables.
```

```text
   STACK MEMORY                    HEAP MEMORY
┌──────────────────┐            ┌──────────────────┐
│        a         ├───────────>│    50 (Object)   │
└──────────────────┘            └──────────────────┘

                                ┌──────────────────┐
                                │ 10 (No reference)│ ──> Collected by Garbage Collector
                                └──────────────────┘
```

* **Garbage Collector:** An automatic process in environments like Java that runs to free up memory by removing objects from Heap that have no active reference variables.

---

# 📌 Key Takeaways

* **Computers execute binary (`0`s and `1`s):** Programming languages translate human code into machine instructions.

* **Procedural vs. Functional vs. OOP:** Procedural follows sequential steps, Functional uses pure functions without side effects, and OOP organizes data and behavior into classes and objects.

* **Static vs. Dynamic:** Static languages check types at compile time (`int a = 10;`); dynamic languages check types at runtime (`a = 10`).

* **Stack vs. Heap:** Reference variables live in Stack memory; actual objects live in Heap memory.

* **Shared References:** Modifying an object in Heap via one reference variable changes it for all references pointing to that object.

* **Garbage Collection:** Automatically clears memory objects that have zero active reference variables pointing to them.
