# 🔀 Flow of Program: Flowcharts & Pseudocode

# 1. 📊 Flowcharts

## What is a Flowchart?

A **flowchart** is a diagrammatic/visual representation of an algorithm or thought process.

---

## Flowchart Symbols

| **Symbol Name**    | **Diagram Shape** | **Purpose / Function**                                                   |
| ------------------ | ----------------- | ------------------------------------------------------------------------ |
| **Start / Stop**   | Oval              | Indicates the starting or ending point of a program.                     |
| **Input / Output** | Parallelogram     | Represents input operations or output displays.                          |
| **Processing**     | Rectangle         | Represents mathematical computations or variable assignments.            |
| **Condition**      | Diamond           | Represents decision-making statements with True/False (Yes/No) branches. |
| **Flow Direction** | Arrow             | Connects shapes to show the direction of program execution.              |

### Example 3: Prime Number Check — Basic Approach

**Prime Number Definition:** A number greater than `1` that is divisible only by `1` and itself.

**Logic:** Test whether any number `c` starting from `2` up to `num - 1` divides `num` evenly (i.e., `num % c == 0`).

If any number divides it, `num` is **Not Prime**.

If no number divides it, `num` is **Prime**.

# 2. 📝 Pseudocode

## What is Pseudocode?

**Pseudocode** is an informal, human-readable outline of a program's logic.

It does not follow strict programming language syntax and is meant for human understanding.

---

## Pseudocode: Salary Bonus Calculation

```text
Start
Input Salary

if Salary > 10000:
    Salary = Salary + 2000
else:
    Salary = Salary + 1000

Output Salary
Exit
```

---

## Pseudocode: Prime Number Check — Basic Approach

```text
Start
Input num

if num <= 1:
    Output "Neither prime nor composite"
    Exit

c = 2

while c < num:
    if num % c == 0:
        Output "Not Prime"
        Exit

    c = c + 1

end while

Output "Prime"
Exit
```

# 3. ⚡ Optimizing the Prime Number Check

## The Factor Observation

Listing all factor pairs of a number such as `36` shows that factors repeat after its square root:

$$
\sqrt{36} = 6
$$

```text
1 × 36 = 36
2 × 18 = 36
3 × 12 = 36
4 × 9  = 36
6 × 6  = 36  ← Square Root (√36)
9 × 4  = 36  ← Repeated
12 × 3 = 36  ← Repeated
18 × 2 = 36  ← Repeated
36 × 1 = 36  ← Repeated
```

Because factor pairs repeat after `√N`, checking divisibility past `√N` is redundant.

---

## Optimization Rule

Instead of checking from:

```text
c = 2
```

up to:

```text
N - 1
```

check only from `c = 2` up to `√N`.

In code, this can be expressed as:

```text
c × c <= N
```

### Example 1 — `N = 17`

**Unoptimized:**

Checks:

```text
2, 3, 4, 5, 6, ..., 16
```

**15 checks**

**Optimized:**

Checks only while:

```text
c × c <= 17
```

Therefore:

```text
c = 2, 3, 4
```

**3 checks**

---

### Example 2 — `N = 23,456,786,543`

**Unoptimized:**
Over **23 billion checks**.

**Optimized:**

$$
\sqrt{23,456,786,543} \approx 153,156
$$

Approximately **153,156 checks**.

---

## Optimized Pseudocode: Prime Check

```text
Start
Input n

if n <= 1:
    Output "Neither prime nor composite"
    Exit

c = 2

while c * c <= n:
    if n % c == 0:
        Output "Not Prime"
        Exit

    c = c + 1

end while

Output "Prime"
Exit
```

# 🔍 Dry Run: Optimized Prime Check

## `N = 36`

### Step 1

```text
n = 36
c = 2
```

Condition:

```text
2 × 2 <= 36
4 <= 36
```

→ **True**

Check:

```text
36 % 2 == 0
```

→ **True**

Output:

```text
"Not Prime"
```

→ **Exit**

---

## `N = 17`

### Step 1

```text
n = 17
c = 2
```

Condition:

```text
2 × 2 <= 17
4 <= 17
```

→ **True**

Check:

```text
17 % 2 == 0
```

→ **False**

Increment:

```text
c = c + 1
c = 3
```

### Step 2

```text
n = 17
c = 3
```

Condition:

```text
3 × 3 <= 17
9 <= 17
```

→ **True**

Check:

```text
17 % 3 == 0
```

→ **False**

Increment:

```text
c = c + 1
c = 4
```

### Step 3

```text
n = 17
c = 4
```

Condition:

```text
4 × 4 <= 17
16 <= 17
```

→ **True**

Check:

```text
17 % 4 == 0
```

→ **False**

Increment:

```text
c = c + 1
c = 5
```

### Step 4

```text
n = 17
c = 5
```

Condition:

```text
5 × 5 <= 17
25 <= 17
```

→ **False**

The loop terminates.

Output:

```text
"Prime"
```

→ **Exit**

# ⏱️ Time Complexity Comparison

| Algorithm                     | Time Complexity | Reason                                                     |
| ----------------------------- | --------------: | ---------------------------------------------------------- |
| **Basic Prime Algorithm**     |          `O(N)` | Checks up to `N - 2` potential divisors in the worst case. |
| **Optimized Prime Algorithm** |         `O(√N)` | Checks only up to `√N` potential divisors.                 |

The optimized approach significantly reduces the number of operations required for large values of `N`.

---

# 📌 Key Takeaways

* **Flowcharts visually map program execution:** Oval (Start/Stop), Parallelogram (I/O), Rectangle (Process), Diamond (Condition), Arrows (Flow).

* **Pseudocode is syntax-free:** Describes algorithm steps in plain human terms without language-specific code rules.

* **Modulo Operator (`%`):** Returns the division remainder (`a % b == 0` indicates `a` is divisible by `b`).

* **Factor Symmetry:** Factors mirror after `√N` (`A × B = N` implies at least one factor is `≤ √N`).

* **Square Root Optimization:** Restricting checking to `c × c <= N` optimizes prime checking time complexity from `O(N)` to `O(√N)`.
