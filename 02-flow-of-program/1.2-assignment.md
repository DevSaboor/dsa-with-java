### Exercise 1 — Even Numbers from `1` to `N`

**Goal**
Practice converting a simple programming problem into a flowchart or pseudocode.

**Task**

Create **either a flowchart or pseudocode** that:

1. Takes a number `N` as input.
2. Finds all even numbers from `1` to `N`.
3. Prints each even number.

**Example**

For:

```text
N = 10
```

The output should contain:

```text
2
4
6
8
10
```

<details>
<summary><b>Click to reveal the Answer</b></summary>

### Pseudocode

```text
Start
Input N

i = 1

while i <= N:
    if i % 2 == 0:
        Output i

    i = i + 1

end while

Exit
```

### Exercise 3 — Edge Case: `n <= 1`

**Goal**
Understand why the prime-checking algorithm handles values less than or equal to `1` separately.

**Task**

Explain:

> Why is `if n <= 1` checked at the start of the prime pseudocode?

Then answer:

* What happens if `n = 1`?
* What happens if `n = 0`?
* Why shouldn't either be classified as prime?

<details>
<summary><b>Click to reveal the Answer</b></summary>

The condition:

```text
if n <= 1:
    Output "Neither prime nor composite"
    Exit
```

handles values that are outside the definition of prime numbers.

A **prime number** is a number greater than `1` that has exactly two positive divisors: `1` and itself.

Therefore:

```text
1 → Neither prime nor composite
0 → Neither prime nor composite
```

Without the check, the algorithm could incorrectly reach the final `"Prime"` output because there are no valid divisors checked by the loop.

</details>

**What this teaches**
Edge-case handling and the importance of validating input before executing the main algorithm.
